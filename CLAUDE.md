# Контекст проекта для Claude

Telegram-бот — помощник продавцов на playerok.com (аналог FunPay Cardinal / Easy Sell),
многопользовательский: каждый продавец подключает свой аккаунт Playerok.
Владелец бота пишет по-русски, с телефона (ПК нет) — отвечать по-русски, коротко,
давать пошаговые инструкции под мобильный интерфейс. Проверять вживую он может только
в Telegram и в Railway; присылает скриншоты.

## Где и как работает

- Ветка разработки: `claude/greeting-h0auao` (Railway деплоит именно её, автодеплой на push).
- Хостинг: Railway, проект `radiant-education`, сервис `silver-dollop`, регион US West.
  Volume `silver-dollop-volume` смонтирован в `/app/data`; база SQLite — `/app/data/bot.db`
  (путь абсолютный, задаётся `DATA_DIR`). При старте в логе: «База: … (файл уже был)» и

## Архитектура (bot/)

- `main.py` — запуск: aiogram-поллинг + фоновый поллер Playerok.
- `playerok/` — GraphQL-клиент. `queries.py` — все запросы. Транспорт curl_cffi с
  имитацией Chrome. Клиент сам чинит запросы: убирает неизвестные поля
  («Cannot query field») и правит типы переменных (`T` → `T!`), кэширует исправленное.
  403 с HTML = защита/геоблок, НЕ истёкшая сессия (не разлогинивать!).
- `services/poller.py` — каждые 30 с: сделки, чаты, лоты → `automation.py`.
- `services/automation.py` — приветствие, автовыдача, автоподтверждение, автоответчик,
  напоминания, тексты после отзывов/проблем, автоподнятие и перевыставление лотов.
- `services/features.py` — реестр функций, шаблоны с переменными `{Имя_Клиента}` и т.п.
- `services/notifications.py` — все уведомления продавцу (9 типов, вкл/выкл, звук).
- `services/analytics.py`, `services/history.py` — аналитика и импорт истории продаж.
- `handlers/` — экраны бота (settings = автоматизация, account = профиль, stats, admin).
- `plugins/` — платные плагины. `access.py` — выдача доступа (`/grant`, `/revoke`,
  `/access`, `/sellers`). `plugins/stars/` — звёзды через Fragment за USDT (TON).
- `db.py` — модели; `_add_missing_columns` досоздаёт новые колонки в старой базе.

## Тесты

`tests/run_all.sh` — все тесты на поддельных Playerok/Fragment/кошельке, без сети.
Гонять перед каждым push. Живой Playerok/Fragment из облачной среды недоступен.

## Что подтверждено вживую

Вход по почте+коду (через прокси), уведомления о заказах/сообщениях/отзывах, загрузка
истории (203 заказа), автовыдача (коды реально уходят покупателям), сохранение базы на
volume.

## Что НЕ проверено / открытые задачи

- Запрос лотов (`items`) отвечал «Access denied» с фильтром `{userId}`; добавлен перебор
  вариантов фильтра (`client.my_items`). Нужно, чтобы владелец нажал «👁 Показать и
  восстановить вручную» и прислал результат. От этого зависят автоподнятие и
  перевыставление.
- Автоподтверждение (`updateDeal` → `SENT`) вживую не подтверждено; при ошибке бот шлёт
  продавцу её текст один раз на заказ. После автовыдачи заказ отмечается выполненным
  автоматически (флаг `autodelivery_confirm`, по умолчанию вкл., переключатель в экране
  Автовыдачи), даже если функция «Автоподтверждение» выключена.
- Перевыставление теперь идёт прямо по сделке (`relist_after_sale`, ID лота из сделки),
  без списка лотов; плюс кнопка «🔄 Выставить заново» в уведомлении о заказе. Работает
  только для сделок, появившихся после этой версии (`DealState.relisted is False`; у
  старых строк NULL). Мутация `publishItem` вживую не подтверждена — при ошибке бот
  шлёт её текст. Платный ли статус размещения, по сделке не узнать.
- Поднятие лота (`increaseItemPriorityStatus`), перевыставление (`publishItem`),
  `markChatAsRead`, отзыв внутри сделки (поля `review` у ItemDeal нет) — запросы
  написаны вслепую.
- Плагин звёзд (Fragment) целиком не проверен: нужны cookies fragment.com, seed отдельного
  кошелька, «🔎 Проверить», затем пробный заказ на 50 звёзд. Методы Fragment — в
  `plugins/stars/fragment.py` (`METHODS`).
- У владельца в запасе автовыдачи могут лежать уже выданные коды (после старого отката
  базы) — напомнить сверить и удалить.

## Автовыдача — как сопоставляется лот

Запас ищется по названию лота без учёта регистра, эмодзи, знаков и лишних пробелов
(`norm_lot`), с запасным совпадением по целым словам (`match_stock_key`). Выдача
повторяется на каждом опросе, пока заказ PAID и не выдан, но только для заказов не старше
24 ч (старые продавец мог закрыть вручную).

## Принятые решения (не пересматривать без причины)

- Не показывать владельцу балансы, токены, seed-фразы и переписки других продавцов —
  ни поштучно, ни в `/sellers`. Допустима только обезличенная сводка числами.
- Seed-фразы и cookies хранятся зашифрованными, сообщения с ними бот удаляет.
- «Вечный онлайн» не делали: неизвестно, как Playerok определяет онлайн.
